# Le projet en bref

- But : réinventer le web comme un métavers léger, qui tourne sur un téléphone ordinaire, et où créer est à la portée de quelqu'un qui ne programme pas.
- Un site s'écrit dans un fichier `.holo`. Par défaut, c'est un site web normal en 2D. Quand on zoome assez, chaque pixel de la page devient un point lumineux ; chaque point se morcelle en d'autres points ; un point peut contenir un monde, ou un autre site. On passe d'un monde à l'autre sans rechargement : seulement du zoom et de l'animation.
- Le moteur est écrit en Rust, compilé en WebAssembly, et dessine avec WebGPU (repli WebGL 2). L'auteur n'écrit jamais de HTML, de CSS ni de JavaScript.
- Règle du langage : à chaque ajout, on compare les options et on vérifie qu'on ne répète pas un défaut de HTML, de CSS ou de JavaScript.

# Le langage aujourd'hui

Un fichier complet, qui emploie presque tout le vocabulaire :

```holo
Page(
  name: Shop,
  title: "My shop",

  // Comment la page se regarde. Ce sont des garde-fous : le visiteur ne les dépasse pas.
  zoom: Zoom(active: true, max: 1000000, shrink: false, levels: 8, speed: 1),
  points: Points(after: 4, size: 6px, fragment: 40px, grid: 4, depth: 20, density: 2),
  relief: Relief(height: 10px, tilt: 360deg),
  portals: Portals(layout: grid, count: 12, size: 170px, brightness: 0.15, duration: 450ms),

  // Ce que la page retient.
  state: State(cart: 0),

  children: [
    H1("My shop"),
    "Paintings made by hand, one at a time.",
    P.card("Free delivery from **30 euros**."),
    Image(source: "painting.svg", weight: 1KB),
    List(children: [ "Sunrise over the river", "The blue door" ]),
    A("The source code", to: "https://example.org"),

    Text("{cart} paintings in your cart"),
    Button(name: Add, text: "Add a painting"),
    Button(name: Remove, text: "Remove one"),
    Button(name: Empty, text: "Empty the cart"),

    Button(name: Open, text: "Enter the workshop"),
    Point(
      name: Workshop, seed: 42, brightness: 0.8, fragments: 6,
      color: "#E9B44C", palette: ["#E9B44C", "#245C45"], budget: 500KB,
      inside: World(
        children: [ H1("The workshop"), Button(name: Back, text: "Back") ],
        rules: [ On(Back.tap, effect: Workshop.leave) ],
      ),
    ),
    Point(name: Garden, seed: 12, inside: "garden.holo"),
  ],

  rules: [
    On(Open.tap, effect: Workshop.enter),
    On(Add.tap, effect: cart.add(1)),
    On(Remove.tap, effect: cart.sub(1)),
    On(Empty.tap, effect: cart.set(0)),
  ],
)

Page { background: #101020; color: white; font-family: Georgia, serif; }
H1 { color: #E9B44C; font-size: 32px; }
.card { border: 1px solid #E9B44C; border-radius: 12px; padding: 8px 16px; }
```

Ce qu'il faut savoir pour lire ce fichier :

- Un bloc commence par une majuscule et ouvre une parenthèse. Un réglage commence par une minuscule et finit par deux-points. Une phrase seule entre guillemets est un paragraphe.
- Blocs existants : `Page`, `Text`, `P`, `H1`, `H2`, `H3`, `A`, `Button`, `Image`, `List`, `Point`, `World`, `On`, `Zoom`, `Points`, `Relief`, `Portals`, `State`.
- Un bloc ne contient aucun code. Une règle `On(signal, effect: demande)` relie un signal (`tap`) à une demande. C'est le moteur qui exécute la demande, pas le bouton.
- Les styles s'écrivent comme en CSS, après le bloc racine. Ils ne disent que l'apparence, jamais la disposition. Ils visent un type de bloc (`P { }`) ou un nom (`.card { }`), rien d'autre. Toute faute est refusée.
- Tout fichier est vérifié avant d'être affiché ; une erreur donne sa ligne.

# Ce qui vient d'être ajouté (4 octobre 2026)

1. **Le panier, première « action avec état ».**
   - `state: State(cart: 0)` déclare une valeur : un nombre entier, de 0 à un milliard.
   - `{cart}` dans un texte l'affiche, et le texte se met à jour tout seul.
   - Trois demandes seulement : `cart.add(1)`, `cart.sub(1)`, `cart.set(0)`. La valeur ne descend pas sous zéro.
   - Limites connues : pas de texte ni de oui/non, pas de condition, pas de total, rien n'est gardé après un rechargement, rien n'est partagé entre visiteurs.
2. **La rotation de la page.** `Relief(tilt: 360deg)` permet de faire le tour de la page et de la voir par derrière. Sans `tilt`, une page ne tourne pas : elle reste un site ordinaire. C'est l'auteur qui active la rotation.
3. **Deux réglages** : `Zoom(speed:)` (vitesse du zoom) et `Portals(duration:)` (durée d'ouverture d'un portail).

# Ma préoccupation du moment

Je veux de la cohérence entre le site normal et le métavers. Si certaines pages peuvent partir en 3D à tout moment, cela gêne la lecture du site. Je pense donc que certaines fonctions (la rotation, le relief, peut-être le passage en points) doivent être **activées par l'auteur**, et non offertes d'office.
